# Slide plan, or a document talked through on a call

**Job.** Be the thing the presenter points at while they talk. They supply the narration; the
artifact supplies the anchors. It is not a document that happens to be on screen — a document
is read, this is spoken over.

## Settle before drafting

- **Slot length**, and how it splits between the artifact and anything shown live.
- **What the audience knows about this specific subject** — often they know the tooling but
  not this project, or the reverse.
- **What they should decide or believe afterwards.**
- **Whether a speaker script is wanted** alongside the artifact.
- **Anything in the room's history** that makes an example land badly — work someone present
  already owns, or a question they are currently arguing about.
- **How the room wants to be walked through it** — starting from the problem they already feel,
  or from the design as built. Order for a live room, not for the order the work happened in.

## Where each point goes

Every point belongs to exactly one place, and gets marked with it:

- **on screen** — short bullets the audience reads
- **spoken** — the presenter says it; at most a short prompt on screen so they remember
- **shown live** — a demo, a tool, a real artifact; not written out

The most common failure is collapsing all three onto the screen. Not everything belongs on
the screen.

## Rules

- No redundancy between what is on screen and what is shown live. One sets up the idea, the
  other is the proof.
- "More detail" on a slide means more, tighter bullets — never longer text.
- Figures, diagrams and worked examples carry more than prose here. Text is for documents.
- Cut anything specific to how this work was built rather than what it does. It costs
  attention and invites questions the presenter did not plan for.

## When the ask is "something to present" rather than a deck

If the request is to show numbers to teammates or a manager, the deliverable is **bare
numbers, the calculation that produced them, and crisp bullets** — not prose and not a
polished document. The author narrates live; the artifact is a glanceable reference.

- Put figures in code blocks or aligned monospace tables.

## If the output is a deck file

Produce the plan in markdown with every point marked by where it goes, and hand that over.
Building the file itself is a separate step and only on request.
